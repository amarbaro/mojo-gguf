# mojo-gguf v0.2.0

**Released:** 2026-11-04 · **Commit:** `883be76` · **Previous:** [v0.1.1](v0.1.1.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
GGUF tools in Mojo that write the bytes llama.cpp's own tools write: a GGUF reader and writer, the four gguf-py
scripts, the Qwen2 safetensors-to-GGUF converter, the LoRA and legacy-GGML converters, eight `llama-quantize --pure`
types and a dequantizer for 19 types. Each is compared with llama.cpp pinned at `1744c6bde`. Linux x86-64, CPU only,
Mojo 1.2.

## Highlights

- Breaking for library users: the package is `ggufx` (`from ggufx import Gguf`), so mojo-gguf installs and links
  next to mojo-gguf-core in one env. Command names are unchanged.
- `gguf-rewrite f f` and `quantize f f` used to truncate the input to 0 bytes; an output that is the input is now
  refused.
- Corrupt safetensors checkpoints, tokenizer.json files and GGUFs are refused with an error instead of being read
  past their bounds, aborting, or printing invalid UTF-8.

## Changes

### Changed
- Package `gguf` is renamed `ggufx`.
- uregex is a dependency (`[tool.mojo] deps`, `scripts/deps.sh` pins mojo-uregex v0.3.2 into `lib/`); builds take
  `-I src -I lib`. The conda recipe depends on `mojo-uregex` instead of shipping its own `uregex.mojoc`.
- `quantize`: NTHREADS 0 or less means all cores.
- `recipe.yaml` (conda package `mojo-gguf`) and `docs/design.md` added.
### Fixed
- The `py_repr` gate pins its oracle Python to 3.14 (`.python-version`), the Unicode 16.0 version the escape table
  was generated from, and names a mismatch.
- Tools refuse an output path that is the input file.
- safetensors tensor offsets, sizes and shapes are validated before `hf2gguf` and `lora2gguf` read them.
- JSON: an absent key no longer wraps into the document root; a lone or mismatched UTF-16 surrogate is an error.
- `hf2gguf` refuses a negative token id; `gguf-dequant` and `quantize` refuse a tensor with no dimensions or
  `ne0 == 0`.
- Strings read from a GGUF decode lossily (U+FFFD) instead of becoming invalid UTF-8; `py_repr` escapes what
  Python's `repr` escapes.
- The library links next to the stdlib's `FileHandle.seek` (`lseek64`) and next to mojo-gguf-core (`open64`
  with 2 arguments).

## Known limits

- The model gates (u1, u3-u8: Qwen2.5-0.5B, a llama.cpp build) were not rerun for this release; they run locally
  with `scripts/oracle-gates.sh`.
- A tokenizer.json that really contains a lone surrogate is now refused.

## Upgrade / run

```
uv sync && scripts/deps.sh                        # new: mojo-uregex into lib/
mojo build -I src -I lib src/hf2gguf.mojo -o hf2gguf
# library code: from gguf import ...  ->  from ggufx import ...
```
